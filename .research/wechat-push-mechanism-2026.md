## 1. 订阅号信息流与平台规则（保留 A/B 级）

### 1.1 信息流的折叠形态

订阅号消息列表里关注号内容会被折叠，需点击"展开更早消息"。具体顺序、卡片显示字数、各入口流量占比**没有官方文档**，所有具体百分比已删除。

定性结论：
- 订阅号内容不再是默认置顶
- 算法分发权重高于时间排序（2020 年 5 月起官方放弃时间线，至 2026 未恢复）

### 1.2 标题展示规则（业界实测）

| 项 | 规则 | 来源等级 |
|---|---|---|
| 标题最大字数 | **64 字**（业界实测，无官方文档） | B（实测） |
| 已发布修改限制 | 字数修改 ≤20 字、最多 1 次（实测） | B（实测） |
| 标题不可修改 | 已发文章的标题文字不可改（实测） | B（实测） |
| Emoji 支持 | 系统 emoji 直接可用 | B |
| 头条封面 | 业界实测约 2.35:1（如 900×383） | B（实测） |
| 分享封面 | 业界实测约 1:1（如 383×383） | B（实测） |

> **不可声称为"官方文档"**：以上尺寸/字数在 mp.weixin.qq.com 后台 UI 有提示，但 developers.weixin.qq.com 没有公开的官方书面文档。article-craft 中可使用这些数字，但措辞应为"业界实测得知"。

## 2. 看一看（RALM 算法）— **作用域仅限"看一看"频道**

### 2.1 RALM 算法事实

- **论文**：Real-time Attention Based Look-alike Model for Recommender System（arXiv:1906.05022）
- **作者**：腾讯团队（Yudan Liu, Kaikai Ge, Xu Zhang, Leyu Lin）
- **会议**：KDD 2019
- **作用域**：论文 abstract 明确说"applied in the look-alike module of WeChat 'Top Stories'"，即**发现页 → 看一看入口**

> **关键修正**：RALM **不是订阅号信息流算法**。前期文档把它当作"订阅号信息流核心算法"是张冠李戴。该算法只解决"看一看"频道的长尾内容触达问题。

**未找到任何官方公开的权重数字**。原文中"40/30/20/10"（打开/互动/分享/完读）已删除——这组数字源自 CSDN 个人博客互相引用，**微信从未官方确认**。

## 3. 完读率（A 级官方定义 + 业界经验）

### 3.1 完读率官方定义

**官方原文**（微信开放社区，公众号技术运营专员 livia 答复 2023-05-24）：

> "是根据文章比例计算的，如果全部读完，需要看完滑动到最后才算读完"

来源：https://developers.weixin.qq.com/community/develop/doc/000a8857660538166ecf9b8f751800

**核心**：完读率 = 用户滑动到文章末尾的比例。

> **删除项**：原文中"停留 ≥ 3 秒才算完播"和"完播率 1.3 倍流量加成"**均无官方依据**，已删除。

### 3.2 完读率优化的可落地写作技巧（业界经验，软建议）

**结构层面（B 级经验）**：
- 导语 ≤ 150 字，**前 100 字内说清"读完这篇能得到什么"**
- 每 300-500 字一个小标题（视觉断点）
- 加粗、引用、颜色标记**每屏 ≥ 1 个**（避免视觉疲劳）
- 末尾给"一句话总结"+下一步行动 → 同时提升完读和互动

**钩子设计（B 级经验）**：
- 开篇 3 句话埋钩子（数字、反差、痛点）
- 中段（40-60% 位置）埋"二级钩子"
- 长文在 70% 位置放金句/结论 → 即使中途退出也被读者记住

> **删除项**：原文"完读率分桶基准（800-1500 字 50-70% 等）"无官方分桶数据，已删除。可以保留"短文容易完读、长文衰减更快"的常识性表述。

## 4. 标题与封面（B 级业界经验）

### 4.1 高点击率标题（业界经验软建议）

万能结构（业界经验）："人群/场景 + 数字/热点 + 痛点/悬念 + 解决方案/反转 + 情绪词"，任选 3-4 个元素。

**技术内容适配（经验）**：
- 数字 + 工具名组合较易得到点击（"5 个 VSCode 插件"）
- 反差 + 时效（"上线半年才发现的隐藏功能"）
- 避免纯技术术语开头

> **删除项**：原文"标题 20-30 字最优"调整为"标题 ≤28 字业界实测建议（信息流卡片完整显示）"。

### 4.2 封面图（B 级业界经验）

**业界经验**：
- 视觉冲击力：高饱和度配色、对比色、大色块
- 信息明确性：关键词大字 / 图标暗示
- 情感共鸣点：人脸、表情、场景符号

**技术内容封面策略（经验）**：
- 抠图人物 + 大字关键词
- 截图 + 标注框
- 统一品牌色，建立"封面识别度"

### 4.3 A/B 测试变通

微信公众号原生不支持 A/B 测试。变通：
- **「修改文章」功能**：发布后字数修改 ≤20 字、1 次机会（实测）。**标题文字不可改**——只能换封面/小改正文
- 跨平台对比（视频号、知乎等）

## 5. 互动信号的相对作用

> 原文给的具体"权重百分比"已删除——微信从未官方公开。

可以保留的定性结论：
- **♡（在看）**：好友可见，社交分发杠杆
- **转发到朋友圈/群**：精准流量
- **收藏**：个人价值标签，不直接带来流量
- **赞**：弱反馈信号
- **留言**：互动信号

### 5.1 文末引导话术模板（业界经验）

| 引导动作 | 话术示例 |
|---|---|
| ♡（在看） | "如果觉得有用，点个「♡」让更多同行看到" |
| 转发 | "把这篇转给那个还在用 XX 的朋友吧" |
| 收藏 | "建议先收藏再看，里面 X 个工具都需要慢慢试" |
| 留言 | "你踩过哪些坑？评论区聊聊" |

**经验**：不要同时引导 4 个动作（"点赞、在看、转发、收藏一键三连"）。一篇文章主推 1-2 个动作即可。

## 7. AI 生成内容的合规要求（A 级官方一手）

### 7.1 国家层面：GB 45438-2025 + 网信办《标识办法》

**A 级官方一手**：

- **GB 45438-2025**《网络安全技术 人工智能生成合成内容标识方法》
  - 强制性国标，**2025-09-01 生效**
  - 发布日：2025-02-28
  - 归口部门：中央网络安全和信息化委员会办公室
  - 来源：openstd.samr.gov.cn

- **网信办《人工智能生成合成内容标识办法》**
  - 14 条；四部门联合发布（网信办、工信部、公安部、国家广电总局）
  - **2025-09-01 生效**
  - 第十条："用户应主动声明并使用标识功能。禁止删除、篡改、伪造或隐匿标识"
  - 来源：https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm

**显式标识要求**：
- 文本：在内容起始/末尾/中间含"人工智能"或"AI"+"生成/合成"字样
- 图片：边角文字提示
- 音视频：同步要求

**隐式标识要求**：文件元数据嵌入字段，字段名包含 "AIGC"。

> **删除项**：GB 45438 全文需从国家标准馆下载 PDF 阅读，前期报告里"显式标识必须在文本开头/末尾加"等位置性细节**未经官方文本验证**——如需在 article-craft 里硬编码位置规则，需先核对官方 PDF。

### 7.2 微信平台规则：《运营规范》"非真人自动化创作"条款

**A 级**（微信团队对媒体的官方回应，2026-04-09）：

> "公众号和服务号不得利用AI、脚本、接口或其他自动化方式，替代真人完成内容创作、发布等流程，也不得传播、推广此类自动化创作的教程或服务"
>
> "微信公众平台一贯鼓励真人创作，平台也鼓励创作者合理使用工具辅助创作、提升创作效率，反对的是完全由自动化程序替代真人完成内容生产的行为"

**三类违规情形**（来自微信对媒体披露的运营规范条文）：
1. 脱离真实创作者表达，利用人工智能等方式**生成、改写、拼接或者搬运**内容
2. 通过脚本、程序托管等**自动化方式批量、连续发布**内容
3. 传播非真人自动化创作的教程、方法或服务

**处罚（官方原文）**：
> "平台将根据违规程度对相关内容采取流量限制、删除等处罚措施；对账号采取能力限制、封禁等措施"

**关键修正**：
- "2025-03-27 发布"日期来自媒体二手报道，**不是官方公告日**
- 这不是"专项公告"，是把条款加进了已有的《运营规范》
- 准确表述：**《微信公众平台运营规范》条款，微信团队 2026-04-09 对媒体确认**

> **删除项**："3 次违规封号 7-30 天"具体数字未在官方原文中找到，已删除。"识别准确率 <30%"等数字也未在官方原文中找到，删除。

### 7.3 关于"AI 写公众号被封号"的真实案例

**A 级**（微信团队回应）：90 后夫妻矩阵号案例（2026-04）

**重要事实**：
- 案例主体：90 后夫妻，2026-04 前后被封
- 操作模式：对标爆款 → AI 生成 → 简易人工审核，3 分钟一篇
- 经营规模：**5000 多个合作账号**，"达人合作分成"模式
- **200 万年收入 ≠ 流量收入**：绝大部分来自向 5000+ 合作账号收取**299 元保证金**

> **关键修正**：
> 1. 这是**矩阵号被封 + 知识付费产品被指控**的复合案例，**不是单号封禁**
> 2. 微信封号针对的是**矩阵 + 自动化批量发布**，不是"AI 辅助单号写作"
> 3. 这是**目前唯一被微信官方公开确认的 AI 相关封号案例**——没有"大规模封号潮"的官方证据
> 4. 微信官方明确表态："鼓励合理使用工具辅助创作、提升创作效率"

### 7.4 微信"创作来源"功能（B 级官方间接）

**功能事实**：
- 功能名称：**"创作来源"**（不是单独的"AI 内容"勾选项）
- 首次上线：2023-09-08
- **四个选项**（4 选 1，不允许多选）：
  1. 内容由 AI 生成
  2. 素材来源官方媒体/网络新闻
  3. 内容剧情演绎仅供娱乐
  4. 个人观点仅供参考
- 显示位置：文末小字、阅读量正上方
- **重要约束**：**发布后不可修改、不可删除**——选错只能删文重发

**对自动化发布工具的影响**：这是硬约束——必须在首次发布前定下来。微信开放社区**没有**该功能的官方开发者文档，**没有 API**。

### 7.5 AI 率阈值

> **整节删除**：原文"AI 率 <20% 安全"、"AI 率 <15% 更佳"等**均无官方依据**。微信**从未**公开过任何 AI 内容比例阈值。网信办《标识办法》第十条要求"用户主动声明"，**也没有量化阈值**。规则是二元的：**是 AI 生成的就要声明，没有比例豁免**。

## 9. 给 article-craft 的建议（修订后）

### 9.1 标题（write skill）

**推荐结构（业界经验，软建议）**：
- ≤28 字（业界实测）
- 钩子三选一：危机预警型 / 反认知型 / 故事钩子型
- 数字 / 工具名 / 痛点至少 1 个

**避坑**：标题与正文核心结论必须一致（"标题党"会被算法降权——官方表态）。

### 9.2 写作（write skill）

**结构经验（B 级）**：
- 导语 ≤ 150 字，前 100 字内点明"读完能得到什么"
- 每 300-500 字一个小标题
- 单段不超过 5 行（移动端阅读舒适度）
- 文末 1-2 个具体引导动作

**个人化注入（业界经验，软建议）**：
- 个人经历（"我去年试过..."）
- 具体数字（"耗时 47 分钟"比"耗时较长"好）
- 主观判断（"我不推荐 X，原因是..."）

### 9.3 review 自检阶段

**新增/强化规则（基于官方证据）**：
- AIGC 显式标识必须存在（GB 45438-2025 强制）
- 文末必须有 1-2 个具体 CTA（业界经验，4 篇实测显示这是真瓶颈）
- 标题钩子检查（≤28 字 + 钩子型）
- 段落相似度去重（防止生成事故）
- GitHub URL 真实性校验

> **删除项**：原"Rule 19 AI 味识别 + 排比检测"、"Rule 20 完读率友好性硬阈值"、"Rule 22 AI 率检测 <20%"等基于伪事实/无依据的项已删除。

### 9.4 封面（share-card）

**业界经验（软建议）**：
- 头条封面约 2.35:1
- 分享封面约 1:1
- 大字关键词 + 对比色 + 视觉锚点
- 不强制具体像素数字（无官方文档）

### 9.5 orchestrator 修订

```
requirements →
  verify →
  [evidence] →
  write →
  screenshot →
  share_card →
  images →
  verify-claims [GitHub URL 真实性] →

  publish
```

> **删除项**：原"ai-rate-check"步骤已删除（无官方依据）。
