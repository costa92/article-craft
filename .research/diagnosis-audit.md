## 审计摘要（5 个最关键发现）

1. **"AI率 < 20% 是合规阈值" 是伪 P0**。所有引用都指向博客园/CSDN/AI 检测工具自卖自夸，**零官方依据**。调研报告自己标 C 级，但诊断报告把它当 P0 硬阈值用（"AI 率 >30% 不允许 publish"）。这条 P0 应直接降级到 P2 提示。
2. **"系列发文 = 自动化批量发布信号" 是过度推论**。微信运营规范条款明确针对"脚本、程序托管批量发布"，所有官方表述指向"账号工厂"（如"爆了么AI"5000账号矩阵）。**人写的系列文章 + 5-10 天间隔**没有任何官方/媒体证据证明会触发风控。第二轮诊断新增 P0-6 是恐慌驱动决策。
3. **AIGC 显式标识 P0 紧迫性确实成立，但实操可被极度简化**。GB45438-2025 是 A 级事实（强制国标 2025-09-01 生效），但文末小字脚注 + 公众号后台勾选"AI 辅助"即合规——不需要"调第三方 API 检测 AI 率"或"AI 率 > 30% block publish"这类重型工程。原 P0 5h 工作量可压到 1h。
4. **第二轮诊断的样本量（4 篇）不足以推翻第一轮**，但**推翻方向是对的**。4 篇全是中文、有"我"叙事、完读率达标——这反驳了第一轮"全英文 Medium 风格"的预设确凿。但"系列文章=违规"、"主观判断需≥3 处分散"等具体阈值依然是过度推论。
5. **"40/30/20/10 算法权重" 在三份文档中地位错乱**。调研报告 §2.5 明确标"等级 B 行业逆向、微信从未官方确认"，**但诊断报告引用时把这条权重当 fact 用**（如"零 CTA = 主动放弃 50% 算法权重"）。这是循环论证 + 单一数字赌注。

## 逐条验证

### R1-1 朋友♡ 占信息流首位 + 36 氪 45.9%

**强度**：强主张 | **支撑**：新浪科技/腾讯新闻 2025-03 报道 | **验证**：WebFetch 新浪原文 + WebSearch 多源

**结果**：事实性 = 部分确认；逻辑 = **有跳跃**
- 36 氪 24.3% → 45.9% 数据 WebFetch 验证准确。
- 但**这是单一矩阵账号"36氪未来消费"的个例**，调研报告把它泛化为"小号普遍优势"。
- **反向证据**：腾讯新闻同源数据显示，**一篇 10 万+ 实测「朋友推荐」入口仅贡献流量 0.02%**（R1-9 同源）。
- 调研搜索还发现："朋友在看功能已被折叠弱化"的反向说法。

**问题**：调研报告同时说"45.9% 流量贡献"和"0.02% 入口贡献"，两个数字差 2000 倍。前者是社交推荐总量（含分享传播），后者是"朋友♡"产品入口本身——但诊断报告 P1-14 引用"45.9%" 时没区分。

**评级**：**B**——产品形态判断正确，但"小号普遍 45.9%"不能直接套用，是单一案例。

### R1-2 算法权重 40/30/20/10

**强度**：弱主张（调研自标 B 行业逆向）| **验证**：WebSearch 多源

**结果**：事实性 = 部分确认（确实是普遍引用的比例）；逻辑 = **典型循环引用**
- 多个 CSDN/jzl/woshipm 文章都引用这组数字，**但都没指向原始数据源**。
- **微信从未官方公布权重**，所有数字都是行业逆向推测。

**问题**：诊断报告 R3-2 说"零 CTA = 主动放弃 50% 算法权重"——这是把行业逆向数字当 fact 用了。**实际无人知道真实权重**。

**评级**：**C**——可作为"四个指标都要做好"的参考，但**禁止当成"30% 权重的硬数字"做决策依据**。

### R1-3 阅读完播率 1.3 倍流量加成

**强度**：强主张但调研自标 C | **验证**：WebSearch

**结果**：事实性 = **无法验证为官方**——所有引用都指向同一篇 CSDN 文章（来源 3，blog.csdn.net/2401_87027887）。
- 调研报告自己已经标"等级 C 单一来源"，**透明度合格**。
- 但诊断报告引用时没保留这个 C 级提示。

**评级**：**C**——单一来源孤证，不应作为规则依据。

### R1-4 新号 30 天保护期 + 数据目标 CTR≥15%/完读≥50%/转发≥8%

**强度**：行业经验 | **验证**：WebFetch jzl.com 原文

**结果**：WebFetch 明确说"非官方机制，行业经验"。**且 CTR≥15% 这个目标极不现实**——R1-7 显示行业平均打开率仅 0.89%，2% 已是优秀。
- 把"15% CTR"当成新号目标，**与同份调研内 R1-7 数据自相矛盾**。
- 调研报告内部数据冲突，没被显式调和。

**问题**：诊断报告 P2-10 用"断更超 3 天报警（垂直度扣分）"作为硬规则，**前提（30 天保护期）本身就没有官方依据**。

**评级**：**C**——参考可，硬规则不可。

### R1-5 GB45438-2025 强制国标

**强度**：强主张 | **验证**：WebSearch 多源（含国家标准全文公开网站 + 普华永道 PDF）

**结果**：事实性 = **完全确认 A 级**。
- 国家标准 openstd.samr.gov.cn 有正式条目。
- 2025-09-01 生效。
- 显式 + 隐式标识要求准确。

**评级**：**A**——铁板钉钉的合规事实。

但**实操层面**：WebSearch 显示微信平台**已提供"内容由 AI 生成"勾选**，发布时勾选即合规，**不需要"调第三方 API 检测 AI 率"**。诊断报告 P0-4 是过度工程。

### R1-6 微信运营规范 2025-03-27 新增条款 + 3 次违规封号 7-30 天

**强度**：强主张 | **验证**：WebSearch 多源（含澎湃新闻、36 氪、虎嗅）

**结果**：事实性 = **部分确认**
- 条款本身确实存在（澎湃 A 级源确认）。
- **但"3 次违规封号 7-30 天"的具体数字**：实际表述是"90 天内累计违规 3 次封禁 15-30 天"。调研报告"3 次以上 7-30 天"是简化（不完全准确）。
- **关键发现**：所有公开报道的封号案例都是**"账号工厂"式大规模运营**（如"爆了么AI"夫妻档：5000 账号 + 3000 达人签约 + 自建提示词工厂）。**个人小号 + AI 辅助创作 + 人工改写**的封号案例**搜不到任何一例**。
- 微信官方明确表态："鼓励合理使用工具辅助创作"。

**问题**：诊断报告把这条解读为"article-craft pipeline 自动化触发条款 1+2"——但条款 2 明确指"脚本程序托管批量发布"，而 article-craft 是**用户主动发起的辅助生成**，不是"托管批量"。**法律解读过于紧张**。

**评级**：**A**（事实）/ **B**（风险解读偏紧）

**强度**：强主张 | **验证**：WebFetch yiban.io 原文

- 0.89% 数字在多个 SEO 站点（yiban.io 等编辑器/工具站）反复出现，疑似互相抄录。

**评级**：**B**（数量级正确，但具体数字未必精准）

### R2-4 5 项 P0 必修

逐项审查：
- **P0-1（AIGC 显式标识）**：A 级合规事实，**保留 P0**，但工时压到 1h（文末脚注 + 后台勾选即可）
- **P0-2（AI 自声明禁用）**：R3-3 已确认 4/4 都没出现，是伪问题。**降至 P3 或删除**
- **P0-3（ai_disclaimer 字段）**：R3-3 合并到 P0-1，**删除**
- **P0-4（AI 率检测 API）**：依赖 R1-10 的 D 级证据，**降至 P2 软提示**
- **P0-5（AI 率 >30% block publish）**：同上，**删除硬阈值**

**评级**：5 项 P0 中**只有 P0-1 站得住**，其他都该降级或删除。

### R3-2 真正卡死的 3 个系统性问题

**强度**：强主张 | **验证**：4 篇数据 + 调研对照

**结果**：
- **CTA 缺失 (4/4)**：B 级证据。WebSearch 显示"在看引导效果已被弱化"——但**文末引导分享/收藏仍是有效操作**。"零 CTA"确实是流量损失，但"50% 算法权重"提法是基于 R1-2 的 C 级数字，话不能说死。
- **AIGC 标识缺失 (4/4)**：A 级合规事实，**确实需要修**。
- **系列发文骨架风险**：见 R3-5 验证，**证据不足**。

**评级**：**B**——CTA 和 AIGC 两点站得住，系列发文这条不站住。

---

### R3-5 新增 P0-6（系列发布合规改造）

**强度**：强主张 | **验证**：WebSearch

**结果**：**未找到任何官方/媒体来源**支持"人写的系列文章 + 5-10 天发文间隔"会被风控当成自动化批量发布。
- 所有官方表述指向"脚本/程序托管"和"账号工厂"。
- 4 篇文章发文间隔是 5/9、5/14、5/20、5/21——**这本身就不是"批量、连续发布"的特征**（"批量"通常指一天数十篇）。
